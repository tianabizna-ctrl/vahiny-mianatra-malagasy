# Reviewing the course as a native speaker

You read the Malagasy; the build takes your word for it. Nothing here overrides a
correction you made — if a rule, a dictionary or the source pack disagrees with
you, you win, and the build prints `correction wins …` so you can see it happen.

## Judging by ear, not by phonetics

You are Malagasy: the respelled hints (`sah-LAH-mah`) are for the learner, not for
you. They are **not shown** on the review sheet. Every row has a **▶ Hevero**
button that plays the actual clip the app will play, plus **Show (slow)**.

Turn on **Listen mode** in the header and it becomes one continuous job: the row
plays, you press a mark, the next row plays. Keys: **Space** play, **1** ✔,
**2** ?, **3** ✘, **j / k** next / previous. You never need the mouse.

| Mark | What it means here |
| --- | --- |
| ✔ | the recording sounds right — approve it |
| ✘ | the recording does **not** sound right (even if the spelling is fine) — the clip must be replaced |
| ✘ + Correct… | the text is wrong too, and you typed what it should say |
| ? | you cannot tell, or you want to skip it for now |

Marks are saved the moment you press them and count as *judged* progress. A row
you played but did not judge shows up under the **Played, not judged** filter.

## The three copies of the sheet

| File | Use it when |
| --- | --- |
| `PROOFREAD_AUDIO.html` (25 MB) | **Easiest.** All 3,373 clips are inside the file. Double-click it, no server, no folder. Also the only copy whose audio works in a sandboxed preview frame. |
| `PROOFREAD.html` (0.8 MB) | Needs `APP/` beside it (paths `APP/media/audio/…`). Good when the whole project folder is on your disk. |
| `APP/PROOFREAD.html` | Same file from inside `APP/` — served at `http://localhost:8788/PROOFREAD.html` when you run `python3 -m http.server 8788` in `APP`. |

All three are generated by `proofread.py`; `--inline-audio` writes the big one.
Never hand-edit any of them.

## If the sound does not play

The sheet now falls back to a real `<audio controls>` player under the phrase when the
browser refuses to start audio on its own, and there is a **Can I hear it?** button in
the header for exactly this. If it is still silent, serve it instead of opening the
file: `cd APP && python3 -m http.server 8788`, then
`http://localhost:8788/PROOFREAD.html`. Details in `RESEARCH/ABIDI.md`.

## The loop

```
python3 RESEARCH/proofread.py            # 1. regenerate the review sheet
#    open PROOFREAD.html in a browser, mark and correct, press "Export corrections"
python3 RESEARCH/apply_corrections.py ~/Downloads/salama_corrections.tsv   # 2. merge
python3 RESEARCH/build_app_data.py       # 3. rebuild the app with your text
python3 RESEARCH/validate_content.py     # 4. check nothing broke
python3 RESEARCH/render_audio.py --mp3 --force-changed   # 5. re-render changed clips
```

Steps 1–4 are safe to repeat. Step 5 needs the model (`--i-accept-noncommercial`
the first time) and only touches clips whose Malagasy text changed.

## What a mark means

| Mark | Stored as | Effect on the app |
| --- | --- | --- |
| ✔ marina | `verdict: "ok"` | `pron_verified: true`, `pron_approx` removed → the learner sees **✓ checked** instead of **(approx.)** |
| ✘ diso | `verdict: "wrong"` | `pron_disputed: true`, kept in the data and reported by the validator |
| ? | `verdict: "unsure"` | recorded only; the app is unchanged |
| typed text | `mg` / `en` in `CORRECTIONS.json` | replaces the course text; the old text is kept as `mg_original` / `en_original` |

Only ✔ and typed text change what the learner sees. A ✘ with no rewrite is a flag,
not an edit — which is deliberate: a known-bad line is better than a guessed one.

## Review order

1. **Sentences** (196 dialogue lines) — the only Malagasy the learner says to a
   real person. One sitting. Highest value per minute, and every one of them has a
   recording.
2. **Phrases** (717) — the phrasebook and greetings.
3. **Words** (2,478; the ~683 taught in the 36 sessions are listed first).
4. **Grammar examples** (291) and **Notes** (161).

## Files

- `RESEARCH/proofread.py` → `PROOFREAD.html` — generator. Never hand-edit the HTML.
- `RESEARCH/apply_corrections.py` — TSV → `RESEARCH/CORRECTIONS.json`.
  - merges by key, so exporting a second batch does not lose the first;
  - skips keys that no longer exist in the build (**reported, never guessed**);
  - refuses a "correction" that repeats the other language's original, because that
    is a shifted spreadsheet column, not a fix;
  - `--report` prints the current state, `--reset` throws it away.
- `RESEARCH/CORRECTIONS.json` — the review record. Keep it; it is the only copy of
  what you decided and why.
- `APP/media/audio/manifest.json` — hash of the text behind every clip, which is how
  `--force-changed` knows exactly which clips are stale.

## Progress

`apply_corrections.py --report` answers "how far did I get" without opening the page.
The page keeps its own progress in this browser's localStorage (`salama_proofread_v1`),
so use the same browser and the same machine, and press **Resume** if it looks empty
after a restart.
